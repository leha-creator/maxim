# mockapi drifted from the contract on error details; small contract gaps closed

**Date:** 2026-10-24 14:25
**Files:** api/openapi.yaml, internal/account/httpapi/handlers.go, mockapi/internal/store/{store,operations,model,post}.go, mockapi/internal/handlers/{admin,auth,blogger,campaigns,catalog,handlers,orders}.go, mockapi/internal/seed/seed.go, mockapi/internal/server/{contract_test,gaps_test}.go, mockapi/README.md
**Severity:** medium

## Problem

The frontend (docs/frontend-api-gaps.md) found that the mock server answered differently from `api/openapi.yaml` and from the real backend:

- `409 campaign_incomplete`: `details.post_problems` had keys `Code`/`Message`, `missing_fields` came as `null`.
- `422` for campaign form and `publish_at` had `details.field` but no `details.reason`; period > 14 days, half-set time pair and window < 1 h were not checked.
- Generic `409 conflict` instead of `inn_taken`, `details.reason = post_version_in_progress`, `nothing_to_update`, `contractor_inactive`.
- Unavailability intervals: no overlap / length / horizon / count checks.
- Every channel update with `rkn_number` re-marked the number as confirmed.
- `placement.dispute` never filled; `admin-channels` answered `501`.

Contract gaps: no `admin_role` in `/me`, no `total` in `PageMeta`, no per-row amounts in `OrderReportRow`, no `POST /notifications/read-all`.

## Root Cause

The mock was written before the real backend fixed the error vocabulary (`details.reason` codes in `domain` `RuleError`/`ConflictError`). The contract was later updated, the backend followed, the mock did not — nothing checked error bodies against the documented codes, because `TestEveryOperation` exercises only success paths. `store.Problem` was a Go struct without json tags marshalled into a `map[string]any`, so the generated (tagged) API types never touched it. `applyCampaignInput` mutated the campaign before validating, so a rejected PATCH still changed data.

## Solution

- `store.Invalid(field, reason, msg)` and `store.ConflictReason(reason, msg, details)` helpers; every mock error now carries the same `details.reason` codes as `internal/*/domain` (copied names, same limits).
- json tags on `store.Problem`; empty slices instead of nil in details.
- Campaign rules ported from `internal/post/domain/campaign.go` and validated on a copy.
- Unavailability rules ported from `internal/channel/domain/unavailability.go`.
- RKN flag changes only when the number actually changes.
- `Placement.Dispute` set on P-14 (deadline T-06 = 72 h) and in seed.
- `admin-channels` implemented in mock (role check `admin_required`, approve with `details.missing`, reject, rkn-check, list with `total`); `adm@example.test` is `senior`; seed channel 113 waits in the moderation queue.
- Contract: `Me.admin_role` (+ `AdminRole` enum, real backend fills it from `user.admin_role`), optional `PageMeta.total` (mock fills it, real backend may omit), required `spent_amount`/`refunded_amount`/`held_amount` in report rows (totals = sum of rows), `markAllNotificationsRead`.
- `[FIX]`-prefixed logs on every new rejection path.

## Prevention

- When a `details.reason` code is added to the real backend `domain`, grep `mockapi/` for the same rule in the same change.
- Never marshal untagged structs into error `details`; use tagged structs or maps.
- Validate input on a copy and assign only on success (mock has no transaction rollback).
- Keep `mockapi/internal/server/gaps_test.go` style tests for error bodies: `TestEveryOperation` only covers 2xx.
