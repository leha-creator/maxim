# Project Roadmap

> Бэкенд биржи рекламы в каналах MAX: рекламодатель выбирает каналы, готовит пост и платит; блогер размещает его на срок; платформа маркирует, контролирует и рассчитывается.

**Границы репозитория.** Здесь делается только бэкенд: Go, один исполняемый файл с режимами `api` и `worker`, PostgreSQL, объектное хранилище (07 §1). Кабинеты на React в этот репозиторий не входят. `docs/`, `docs/wireframe/` и `mockapi/` остаются как справочные материалы: по ним понятно, что видит пользователь и какое API ждут кабинеты. Внешний договор бэкенда — `api/openapi.yaml`; каждый этап реализует свои операции и дополняет спецификацию.

## Milestones

- [x] **Проектная документация** — концепция, сценарии, машина состояний размещения, модель данных, интеграции, финансы и право, нефункциональные требования, схема экранов
- [x] **Контракт API кабинетов и тестовый сервер** — OpenAPI кабинетов рекламодателя и блогера, заглушка в памяти со Swagger UI для прохода сценариев руками
- [ ] **Проверки и доступы** — бот MAX на ИП, ответы Рокет Ворк, решение «агент или перепродавец», живые прогоны MAX и тестового контура Яндекс ОРД
- [x] **Каркас бэкенда и аккаунты** — режимы `api`/`worker`, конфигурация из окружения с проверкой, миграции PostgreSQL, журнал JSON по 07 §5, метрики и проверки готовности, подменяемые часы, тесты на настоящей PostgreSQL, CI; вход по почте с кодом, сессии, защита от подделки запросов, ограничение частоты, организации, роли, реквизиты, принятие оферт, журнал действий
- [x] **Планировщик заданий и интеграционный слой** — таблица `job` с повторами, ключами уникальности и правилами после простоя; `inbound_event` и `outbound_request`; адаптеры внешних систем с поддельными реализациями; ограничитель запросов MAX; поиск зависших объектов и оповещения
- [x] **Подключение каналов** — адаптер MAX Bot API, приём Webhook с проверкой подлинности, подключение канала кодом, проверка прав бота, реакция на отзыв прав
- [x] **Каталог** — метрики каналов по расписанию, категории, цены по форматам, недоступность, модерация каналов, проверка реестра РКН, фильтры и сортировка
- [x] **Медиатека и пост** — загрузка в хранилище с проверкой типа и размера, производные с плашкой (название и ИНН), документ редактора и сериализация в форматирование MAX, распознавание ссылок, предпросмотр, версии поста
- [x] **Заказ и размещения** — корзина, оформление заказа (кампании и их пост перенесены в «Медиатека и пост»; здесь — состояния `ordered`, `archived`, `order_id`, `checkoutCampaign`, полнота кампании при оплате), одна таблица переходов P-01 … P-18, таймеры, инварианты I-01 … I-13 (без денег)
- [x] **Автопостинг и контроль** — публикация и снятие по расписанию, сверка факта с планом, контроль «часов в топе», нарушения
- [x] **Маркировка через Яндекс ОРД** — организации, договоры, площадки, креативы, erid в посте, опрос статусов, один код ККТУ из конфигурации
- [x] **Приём оплаты и учёт денег** — журнал проводок с ключами идемпотентности, счета и сопоставление поступлений, удержание по размещениям, проверка сходимости, закрывающие документы
- [x] **Выплаты блогерам через Рокет Ворк** — онбординг исполнителя, выплата после приёмки, чеки, статусы, вебхуки и опрос, контроль депозита
- [x] **Приёмка, споры и возвраты** — автоприёмка, претензии, решения администратора, полный и пропорциональный возврат
- [x] **Уведомления и отчёт по кампании** — задание `send_notification`, бот MAX и почта, уведомления в кабинете, просмотры и ссылки по каждому размещению, UTM-метки
- [ ] **API администратора и отчётность ОРД** — операции администратора в OpenAPI и их реализация: модерация каналов и постов, споры, ручные операции с подтверждением вторым администратором, реестр выплат, блокировки, справочники; ежемесячная статистика и акты в ОРД
- [ ] **Юридическая и эксплуатационная готовность, пилот** — сборка образа, выпуск без простоя, резервные копии и проверка восстановления, тестовое окружение с тестовыми контурами внешних систем, оферты и правила площадки, персональные данные, уведомление РКН, запуск на первых каналах
  - Сделано в репозитории (план `plans/ops-readiness.md`): образ бэкенда и `maxim-postgres`, стек `deploy/app` с выпуском без простоя и откатом (`release.sh`, `release.yml` вручную), проверка миграций, резервные копии базы и объектов, проверка восстановления и восстановление на момент времени, шаблоны окружений с подделками и тестовыми контурами, CI `ops.yml` с репетициями; материалы `docs/launch/` (чек-лист, задание юристу, ПДн, черновик уведомления РКН, план пилота).
  - Осталось людям: серверы, корзины, домены, доступы и секреты, GitHub Environments; тексты оферт, правил и политики ПДн (Q-31, Q-33), решение «агент или перепродавец» (Q-02); подача уведомления РКН; сертификат Минцифры; первая проверка восстановления с протоколом; отбор участников и сам пилот. Переменные выплат, уведомлений, споров и API администратора — дописать после слияния их этапов (план, «Что дописать»).
