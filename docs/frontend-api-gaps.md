# Замечания фронтенда к API и mockapi

Что нашлось при вёрстке кабинетов в `maxim-frontend` (вехи MAXI-42 … MAXI-52) и чего фронтенду не хватает в `api/openapi.yaml` и `mockapi/`. Пока замечание не закрыто, фронт обходится сам: считает на клиенте, делает лишние запросы или показывает заглушку. Ключи `MAXI-…` — задачи «ждёт бэкенд» в Tasker, там те же списки.

Состояние на 2026-10-24.

Метки:

- **Контракт** — в `openapi.yaml` нет операции или поля.
- **mockapi** — тестовый сервер ведёт себя не так, как написано в контракте, или не реализует операцию.

## Общее

- **Контракт.** В `/me` нет признака администратора и роли (`moderator`, `senior`). Экраны `adm/*` открыты любой сессии, права проверяет только API, а фронт на 403 показывает «Нет доступа».
- **Контракт.** Списки листаются по курсору, а общего числа записей (`total`) нет нигде. Из-за этого нельзя показать «Показано N из M», число страниц и счётчики вроде «N активных кампаний».
- **Контракт.** Поиск по названию в списках (каталог, кампании, заказы, каналы администратора) отсутствует. Фронт ищет только внутри загруженной страницы.

## Вход и регистрация (MAXI-42)

- **Контракт / mockapi.** ИНН, который уже зарегистрирован, приходит как общий `409 conflict`, а в перечне ошибок есть `inn_taken`. Нужно выбрать один вариант.
- **Контракт.** На `401` при неверном коде входа не сообщается, сколько попыток осталось.

## Каталог и карточка канала (MAXI-43)

- **Контракт.** В карточке канала нет признака «Занято размещением» и отметки «Проверен».
- **Контракт.** В каталоге нет общего числа каналов.

## Каналы блогера (MAXI-48)

- **Контракт.** В API канала блогера нет метрик, поэтому блок метрик и доступности на `blg/channel` не сделан.
- **Контракт.** В списке каналов нет числа заявок для счётчика «Заявки (N)».
- **mockapi.** Не проверяет пересечение интервалов недоступности и их лимит. Тексты ошибок проверены только тестами фронта.
- **mockapi.** Отметка о подтверждении номера РКН ставится всякий раз, когда номер есть в запросе на обновление канала. Фронт отправляет только изменённые поля.

## Корзина и кампании (MAXI-44, ждёт бэкенд: MAXI-135)

- **Контракт.** Нет операции архивирования кампании. Кнопка «В архив» неактивна.
- **mockapi, ошибка.** В ответе `409 campaign_incomplete` у `details.post_problems` ключи `Code`/`Message` вместо `code`/`message`, а `missing_fields` приходит `null`. Экран оплаты не может назвать конкретную проблему поста.
- **mockapi.** Ответ `422` на требования кампании приходит без `details.reason`. Сервер не проверяет период длиннее 14 дней, время без пары и окно короче часа (A-39); сейчас эти правила проверяет только клиент.
- **Контракт.** В `CartItem` нет метрик и цен канала. Корзина запрашивает карточку каждого канала отдельно, до 50 запросов.
- **Контракт.** В `Campaign` нет выдержки из поста, числа каналов и номера заказа. Список кампаний дозапрашивает пост и заказ по каждой строке, до 40 запросов на страницу.
- **Контракт.** `listCampaigns` принимает только один `status`, поэтому «скрыть архивные» фильтруется на клиенте.

## Заказы, размещения и отчёт рекламодателя (MAXI-46, ждёт бэкенд: MAXI-147)

- **Контракт.** Нет API переписки по спору и сводки спора.
- **mockapi.** Никогда не заполняет `placement.dispute`.
- **mockapi.** Конфликт версии поста приходит как `conflict` с `details.post_version_status` (и `details.status` для завершённого заказа), а по контракту ожидается `details.reason = post_version_in_progress`. Код `nothing_to_update` не возвращается вовсе.
- **Контракт.** В `Order` нет итогов по удержанному и возвращённому. Фронт считает их по размещениям.
- **Конфигурация.** Не задан контакт поддержки для размещений, которые рекламодатель не может отменить сам. Сейчас там текст без ссылки.

## Баланс, счета и реквизиты рекламодателя (MAXI-47)

- **Контракт.** У `/balance/transactions` нет фильтра по типу операции (`kind`) и общего числа записей.
- **Контракт.** Пустой строкой нельзя очистить банковские реквизиты, поэтому все четыре поля обязательны.
- **Вопрос.** В Figma название организации в профиле заблокировано, а API разрешает его менять. Нужно решение.

## Размещения, выплаты и реквизиты блогера (MAXI-49, ждёт бэкенд: MAXI-123)

- **Контракт / mockapi.** Если блогер принимает запрос без подключённого Рокет Ворка, приходит `409 conflict` с подсказкой, а не `details.reason = contractor_inactive`. Фронт распознаёт случай по подсказке.
- **mockapi.** `422 validation_failed` при планировании публикации приходит с `field`, но без `reason`, поэтому текст ошибки общий.
- **Контракт.** Нет занятых интервалов канала, поэтому не показать полосу занятости.
- **Контракт.** Нет сводки по выплатам. Итоги считаются на клиенте по загруженным страницам.
- **Контракт.** Нет причины блокировки.
- **Контракт.** Нет имени и даты загрузки документа о режиме налогообложения.
- **Контракт.** Нет даты принятия оферты, вместо неё показана дата публикации документа.
- **Контракт.** Причина отказа от запроса передаётся свободным текстом в `comment`.
- **Бэкенд.** Выплаты и Рокет Ворк на настоящем сервере отвечают `501`.
